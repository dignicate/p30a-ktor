## Running with Docker Compose

If your Ktor application depends on MongoDB, you can use `docker-compose.yml` to run both services together in a unified environment.

This approach is recommended for local development and integration testing.

---

### How to Run

```bash
# 1. Build the Ktor application (creates installDist output)
./gradlew installDist

# 2. Start both Ktor and MongoDB using Docker Compose
docker compose up --build
```

This will:

- Build the Docker image for Ktor from your local source
- Start a MongoDB container (`mongo:5.0`) on an isolated Docker network
- Launch your Ktor server at `http://localhost:8080`
- Allow Ktor to connect to MongoDB via `mongodb://mongo:27017`

---

### Environment Variables

Docker Compose sets the following environment variable for the Ktor container:

```yaml
environment:
  - MONGO_URI=mongodb://mongo:27017
```

In your Ktor app, you should access this value via `System.getenv("MONGO_URI")`  
or, if you're using `application.conf`:

```hocon
mongodb {
  uri = ${?MONGO_URI}
}
```

---

### Recommended Project Structure

```
your-project/
├── build.gradle.kts
├── docker-compose.yml
├── Dockerfile
├── src/
└── build/install/ktor-app/    # Generated by ./gradlew installDist
```

---

### Stopping the Containers

To stop and remove the containers:

```bash
docker compose down
```

> MongoDB data will persist in the `mongo-data` Docker volume unless explicitly removed.

---

### Tip

If you already have MongoDB running on your host system,  
you can skip the `mongo` service in `docker-compose.yml` and run only the Ktor app:

```bash
docker build -t my-ktor-app .
docker run -p 8080:8080 my-ktor-app
```

Make sure to set `MONGO_URI` to match your host MongoDB address (e.g., `host.docker.internal` or `172.17.0.1`).
